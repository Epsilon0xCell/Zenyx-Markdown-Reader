Zenyx-Markdown-Reader

Zenyx is a single file program, zenyx.py, a Markdown reader and renderer in the spirit of a ReadMe style reader. Point it at a README or any Markdown file and read it in the terminal, or turn it into a standalone HTML page.

Standard library only, nothing to install.

Get Zenyx on GitHub

Second pool: the three ways out of a shell

python3 zenyx.py README.md                 # read in the terminal (ANSI colour on a TTY)
python3 zenyx.py README.md --plain         # terminal text without colour
python3 zenyx.py README.md --html          # standalone HTML page to stdout
python3 zenyx.py README.md --html -o page.html
cat README.md | python3 zenyx.py -         # read from stdin

Reading from a pipe works by naming a dash as the file, so a file piped in is read from stdin.

Third pool: what fits through the opening

ATX headings from one hash to six, bold, italic, strikethrough, inline code, fenced code blocks whose contents are never reformatted, links and images, unordered lists, ordered lists that keep their starting number, blockquotes, horizontal rules, and pipe tables, which appear as aligned text in the terminal and as a real table element in HTML.

Fourth pool: the inspection at the door

In HTML output, link and image destinations are tested against an allowed list of schemes: http, https, and mailto, plus relative paths and hash anchors. Any other scheme is replaced with a hash, so a file written by someone else cannot plant a clickable script in a page rendered from it. This is a security check inside the rendering, not a reading feature.

The check reads a destination the way a browser does: leading spaces and control characters are stripped, and tab, carriage return, and newline characters inside the destination are removed before the scheme is read, so a scheme spelled with a tab inside it is still caught.

Fifth pool: library use and honest limits

from zenyx import render
text = render(open("README.md").read(), "plain")   # or "ansi" / "html"

Any other mode name raises ValueError instead of quietly returning plain text. Errors are plain too: a missing file, a directory, or a file that is not valid UTF-8 gets a short error on stderr and exit code 2, with no traceback.

The limits the code comments admit, stated here rather than buried: code spans written with double backticks are cut at the first inner backtick; a link destination containing a closing parenthesis is cut short at that character; and the double underscore form of bold can still trigger in the middle of a word even though the italic patterns guard against it.
